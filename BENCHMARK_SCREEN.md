# Long-budget research screen

The completed six-model study supplies measured timing and development evidence:
[DGX audit](results/robust-timed-cv/README.md). Broaden configurations before
repeating every one across fifteen fits. Prepare independent, frozen studies
by research question; the helper does not submit jobs.

## Fixed training and scoring

Every trainable screened fit runs **100 epochs × 20,000 replacement draws**,
batch 64, microbatch 8: **313 Adam updates/epoch, 31,300 updates and two million
draws per fit**. All examples in the chosen full training pool remain eligible.
These remain sampled epochs, rather than 100 exhaustive corpus passes.
Parameter-free controls score once with zero optimizer steps.

`--fixed-epochs` disables early stopping and scores the **final** trained state.
Validation-selected early checkpoints are not substituted for that state.
Family refits consequently use the same 100-epoch budget. This policy differs
from the previous early-stop/best-checkpoint experiment; do not pool its scores
with the new ones. Monitor 2,048 validation examples for curves, but score the
**whole validation fold** at the end (`--final-eval-sentences 0`). Full held-out
scoring is reserved for the confirmation refits.

Development/test remains grouped 80/20, split seed 2026. Discovery uses **three
exhaustive development folds, seed 42**: approximately **53.33/26.67/20**
train/validation/test fractions of sentence groups. Confirmation uses **five
folds and seeds 42/43/44**: approximately **64/16/20**. The test split stays
untouched throughout discovery. Three folds with a shared seed support screening;
they do not establish initialization robustness or a formal significance claim.

Both full sources are the default. `--datasets phrases` or `--datasets cleaned`
select a complete source pool while preserving vocabulary from **both complete
sources**. The phrases-only cohort is intentionally a small-domain ablation,
not an emergency-sized replacement for the main corpus. Changing source changes
the evaluated population; compare architectures within a cohort rather than
attributing raw score differences solely to training-source quality. Varying
window 2/4/8 keeps the full source pool. The CBOW cohort conditions on both sides
of a masked target, to complement the current causal-prefix comparison.

| `cleaned` | 5 | 15 | Full cleaned-source domain |
| `phrases` | 5 | 15 | Full phrases-source domain |
| `cbow` | 7 | 21 | Matched bidirectional target task, including wider BERT |
| **Merged main + optional cohorts** | **79** | **237** | **Screen first; do not multiply every configuration by fifteen fits** |

For the broad study, use `main`: it merges the first five causal research blocks
and avoids 30 repeated baseline fits. Together with the five optional cohorts,
this is 237 distinct fits. Do not also run those five standalone blocks with
identical settings. Running all standalone blocks would instead cost 267 fits,
including repeated anchors. For a narrower question, run `reference` first,
then prioritize hybrid circuit and trainability controls
using development results and measured costs. Other blocks remain ready to
prepare when their question warrants the allocation. This is a staged plan,
not an instruction to submit every cohort automatically. It avoids a Cartesian
product of learning rate, width/depth, circuit, data and context settings.
The two extra BERT capacity variants start at LR 0.003; tune promising capacities
with the same LR budget before confirmation. A single LR is not an optimized
baseline, and this screen does not establish an architecture-independent ranking.

XX/ZZ gates are generated by Pauli interactions; CRZ is a controlled diagonal
rotation. The comparison keeps the classical word-prediction objective. It
does not implement graph/Laplacian energy minimization or establish a semantic
Hamiltonian theory. Those remain research questions described in
[BENCHMARK_RESEARCH.md](BENCHMARK_RESEARCH.md).

The dimension pilot also runs the existing CUDA synthetic gradient probe over
2/4/6/8 qubits, depths 2/8, initialization 0.05/1 and 32 initialization seeds.
Its records are saved under `trainability-probe/`, separately from NLP fits.
Local/global-observable variance illustrates a possible barren-plateau mechanism;
it is not an NLP loss experiment. Pilot probe/profile/estimate costs are excluded
from repeated-fit timing forecasts. Changing latent size also changes encoder/
head capacity: inspect matched identity controls and per-layer gradient traces,
not accuracy alone. Gaussian small initialization is not exact identity-block
initialization. See [TRAINABILITY.md](TRAINABILITY.md).

## Prepare and calibrate on DGX

Finish any active jobs before pulling; preserve old study folders and manifests.
Use relative commands from the repository directory, without `set -e` in the
interactive SSH shell:

```bash
git pull --ff-only &&
uv sync --locked
```

```bash
bash scripts/prepare_benchmark_screen.sh main --dry-run
```

```bash
PREPARED_STUDY=$(bash scripts/prepare_benchmark_screen.sh main) &&
STUDY="${PREPARED_STUDY##* CV tasks at }" &&
test -f "$STUDY/manifest.json" &&
printf '%s\n' "$STUDY" | tee outputs/robust-screen-study.txt
```

```bash
.venv/bin/python scripts/submit_robust_benchmark.py "$STUDY" --stage pilot
```

Use `reference` in place of `main` for just the 54-fit baseline/LR screen.
The `main` pilot is a **full-budget first CV fit**, plus batch profiling of every arm in
the prepared block. It occupies one 10 GB MIG, via `sbatch`; `prod10` does not
accept interactive jobs. CBOW-only pilots now profile the CBOW objective.
After the pilot completes with exit `0:0`, inspect `compute.json`: it contains
per-configuration estimates at **100 epochs**, full prepared evaluation sizes,
the measured-profile device and a stated 20-second fixed-job allowance. The
allowance is grounded in the old shallow-study overhead; it is not an exact
measurement of every new block. Checkpoints, queue waits, pilot calibration and
human handoff remain outside the modeled costs. End-to-end fit timings replace
profile extrapolation as each block completes.

```bash
scontrol show partition prod10
cat "$STUDY/compute.json"
```

The existing script requests 12 hours per job. Deeper 14-qubit QCSE with the new
budget may exceed that. If `MaxTime` permits 24 hours and the measured estimates
fit it, use:

```bash
.venv/bin/python scripts/submit_robust_benchmark.py "$STUDY" \
  --concurrency 4 --sbatch-option=--time=24:00:00
```

Otherwise retain the permitted wall time. Completed epochs are checkpointed;
after the whole array is terminal, resubmitting the same frozen study resumes
unfinished fits and skips valid completed results. This may repeat preflights
and lose the last incomplete epoch. Do not edit source/manifest while resuming.
For blocks whose measured longest fit is safely within 12 hours, use the default:

```bash
.venv/bin/python scripts/submit_robust_benchmark.py "$STUDY" --concurrency 4
```

Every allocation requests one `1g.10gb` instance; the submitter rejects more than
four concurrent jobs and overlapping unfinished `prod10` submissions. Run blocks
sequentially with this launcher; independent manual submissions are outside its
checkout lock. No code-level guard enforces an account-wide administrator QoS.

## Analyze before confirmation

Run `status`, the allocation-aware timing report and `select` after every block.
Read all candidates in `selection.json`; do not run the screening refits or
inspect test results while choosing architectures/hyperparameters. Record which
questions/controls will be confirmed before submitting their test stage.

Choose a small set: a QCSE configuration, a hybrid circuit and its identity
control at the same latent size, MLP and BERT, with development-tuned learning
rates. Prepare those named arms with `--folds 5 --seeds 42 43 44`, the same
100 × 20,000 budget and full final scoring. For five arms this is **75 CV fits**,
not another sweep of all screening candidates.

Add `--refit-controls` with the selected identity arm's exact name before
preparation. It is retained even if another hybrid wins that family; duplicate
refits are removed. This gives the paired circuit/control held-out comparison
that the old four-family/12-refit plan omitted. The exact final refit count comes
from `selection.json` (typically 15 for these five configurations and three seeds).
Bootstrap held-out differences by complete sentence groups and retain all seeds,
predictions, checkpoints, timings and accounting. Treat screening rankings as
exploratory and report confirmation separately.

Longer runs, full evaluation and new variants need actual CUDA pilots. The old
six-arm timings are a measured anchor, not measured timings for every new setup.
